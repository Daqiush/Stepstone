| 条件 | 路径 | DAT_004b6c78[] | 说明 |

## hands/4 文件格式

### Index 文件

每条记录格式（变长）：

```
[文件名 ASCII 字符串][0x00 空字节][3 字节大端序偏移量]
```

示例（xxd）：
```
A1.LIN\0  00 00 00   → Data 文件 offset=0
A10.LIN\0 00 16 4F   → offset=5711
A11.LIN\0 00 2B 59   → offset=11097
```

解码：`offset = byte1<<16 | byte2<<8 | byte3`（程序内用 FPU 浮点乘法 + `__ftol` 完成）

对应代码：`FUN_004351bd`（bm2000.exe.c ~23584 行）——遍历 Index，找到目标文件名后将偏移存入 `DAT_0047cae4`，再对 Data 文件执行 `fseek`。

### Data 文件

纯文本，所有题目直接首尾相连，无分隔符。Index 的偏移量指向题目内某一具体页（`pg||`）或新题开始（`st||`）的位置，可以指向题目中途。

#### LIN 标签速查

| 标签 | 含义 |
|------|------|
| `st` | 题目记录开始（可在 Data 中途出现） |
| `nt` | 标题/注释 |
| `sk` | 得分 |
| `md\|N\|S,W,N\|` | 发牌：N=庄家席位(1=南,2=西,3=北,4=东)；S/N大写=SHDC，W小写=shdc；东家=剩余（也可显式给第4手） |
| `md\|0,c1,,c3\|` | **行内牌张修改**（见下节） |
| `mb` | 叫牌步骤 |
| `cb` | 最终合同 |
| `cg` | 目标墩数 |
| `cr` | 合同结果 |
| `pc` | 出牌（`pc\|S5\|` = 黑桃5，`pc\|!hk\|` = 红心K强制） |
| `pg` | 翻页（步骤分隔） |
| `up\|N\|` | 回退 N 页 |
| `at` | 步骤说明文字（至下一 `pg` 为止） |
| `hs\|XY\|` | 高亮花色（X=玩家缩写，Y=花色） |
| `ls\|XY\|` | 上一张出牌（花色） |
| `hc\|card\|` | 高亮具体牌张 |
| `lc\|card\|` | 上一张具体牌张 |
| `tc\|c\|` / `tc\|r\|` | 开始 / 结束一墩的显示 |

## 行内牌张修改机制（`md|0,...|`）

格式：`md|0,[seat1_cards],[seat2_cards],[seat3_cards]|`
- seat1=南，seat2=西，seat3=北；东家隐式得到相应变化
- 指定的牌张从持有方移入目标手中（程序内重建 `DAT_004b8ab8` 持有权数组）

通常与 `up|N|` 连用，形成分支：
```
pg||...（正确路线）...

pg||up|3|md|0,ht,,h6|at|如果西家有红心T...（分支A）

pg||up|1|md|0,hqj6,,d87ct|at|如果西家有QJ6...（分支B）
```

### 两种使用模式

**对抗性（惩罚错误打法）**：
- 题目中存在多个预设东西家分布（场景）
- 庄家走错误路线 → 程序激活该路线下能击败合同的分布
- 两次独立失败可展示彼此矛盾的东西家手牌（因为每次激活不同场景）

**协作性/教学性（奖励正确技术）**：
- 适用于多种东西家分布均能打成合同的情况
- 庄家猜哪种分布，`md` 就切换成哪种，展示对应技术路线成立
- 例：`hands/4/Data` 中的 7♣ 将吃叩牌题（A11附近）：东家2-4-3-4与2-3-4-4两种牌型均可应对，猜错后系统顺着庄家的判断切换分布

判断是哪种模式的依据：**该场景的所有分布是否都能打成合同**。能打成 → 协作；存在无法打成的分布 → 对抗。

## 出牌模式与失败判定

### 庄家出牌验证

`FUN_00405abf`（~7648行）**仅在步骤类型=3（填空式选牌测验）时触发**，执行即时对错反馈。

出牌练习（步骤类型=99/10）走完全不同的路径：
- `FUN_00402e7b` 仅验证"此牌是否属于当前座位"（`DAT_004b8ab8[rank*4+suit*0x3c] == seat`）
- 验证通过即提交，无答案比对，错牌照常入账
- 游戏继续进行，直至失败条件触发

### 失败判定（`FUN_0041a4d7`，~12207行）

每墩结束（`DAT_004aff10 == 5`）时更新墩数并检查：

```c
DAT_004b6c38++;  // 东西家赢墩 +1
if (13 - DAT_004b6c38 < DAT_004afe34) {
    DAT_004ad91c = 1;  // 已不可能完约 → 设"宕"标记
}
```

`DAT_004ad91c = 1` 被设置后，`FUN_00431ddc` 写入"Incorrect"字符串，下次重绘时显示。  
**玩家看到提示的时刻是防守方积累了足够墩的那一刻，或玩家主动 Claim 时**，而非出错牌的瞬间。

## 防守跟牌逻辑

### 情形一：庄家出预期牌（`FUN_00438e94` ~25460行）

```c
suit = DAT_004b6c78[DAT_004b4498] / 10;
rank = DAT_004b6c78[DAT_004b4498] % 10;
DAT_004b4498++;
```

直接从预存序列取下一张牌，按顺序播放，无任何条件判断。

### DAT_004b6d64：自由模式计数器

- 初始值 `0`
- `DAT_004b6c78[i]` 中 suit=0, rank=1 的条目为"自由标记"，读到时 `DAT_004b6d64++`（~12689行）
- `DAT_004b64b4==2 && DAT_004b6d64>=3` → 序列视为耗尽，转入 `FUN_00416b55`（~25425行条件）
- 每墩结算时重置为 0（~12664行）

---

### 情形二：庄家出意外牌（`FUN_00438e94` ~25439行）

```c
if (played_card != DAT_004b6c78[DAT_004b4498]) {
    DAT_004b6c78[DAT_004b4498] = played_card;  // 用实际出牌覆写当前位置
    DAT_004ad614 = DAT_004b4498 + 1;           // 序列在此截断
    DAT_004b8be8 = 0;                          // 清空树形序列
    DAT_004addb0 = 1;
}
```

截断后 `DAT_004b4498 == DAT_004ad614`，预存序列耗尽，`DAT_004b6d64 = 3`（自由模式），转由 `FUN_00416b55` 接管。

### `FUN_00416b55`（~10825行）：序列耗尽后的防守逻辑

按优先级依次尝试：

**① 高打**：在东西家中找到同花色且点数高于当前赢牌的最高牌
```c
for (rank = 14; rank > current_winning_rank; rank--) {
    if (DAT_004b8ab8[rank*4 + ew_seat*0x3c] == lead_suit)
        return ew_seat * 0x1e + rank;
}
```

**② 脚本防守 + 卡牌互换**：遍历 `DAT_004b64c0[]`（从树节点 `+0x50` 加载的预设防守序列）
```c
iVar3 = DAT_004b64c0[i];          // suit*0x14 + rank，负值=此处应出
seat = DAT_004b8ab8[rank*4 + suit*0x3c];

if (seat != expected_ew_seat) {
    // 持有权在错误的 E/W 方 → 就地互换
    DAT_004b8ab8[other_rank*4 + other_seat*0x3c] = expected_seat;  // 行10953
    DAT_004b8ab8[rank*4     + suit*0x3c]         = original_seat;  // 行10954
}
return expected_seat * 0x1e + rank;
```

**③ minimax 回退**：`FUN_004188b6` 递归双明手求解

### 换牌与 minimax 的矛盾消解：懒惰确定策略

BM2000 用**换牌先于 minimax**解决"动态手牌 vs 双明手只能处理确定局面"的矛盾：

1. `FUN_00416b55` 按优先级：① 高打 → ② 脚本换牌 → ③ minimax
2. 步骤②执行时立即修改 `DAT_004b8ab8`，将目标牌归入正确座位
3. 步骤③调用 `FUN_004188b6` 时，`DAT_004b8ab8` 已是完全确定的局面

牌的归属在游戏过程中按需动态确定（lazy determination），minimax 始终看到一个干净的快照，不需要处理不确定性。

### "矛盾手牌"根源

两次错误打法触发 `DAT_004b64c0[]` 中不同条目的互换操作：每次互换在 `DAT_004b8ab8` 中把同一张牌（如 ♠K）分配给不同的 E/W 方，导致两次失败展示的东西家持牌彼此矛盾。**这是代码层面的动态赋牌，不是预先写死的两副牌。**

### 对比总结

| | 庄家出预期牌 | 庄家出意外牌 |
|--|------------|------------|
| 防守来源 | `DAT_004b6c78[]` 固定序列 | `DAT_004b64c0[]` 脚本 + 卡牌互换 |
| 修改 `DAT_004b8ab8` | 否 | **是**（`FUN_00416b55` 行10953-10954） |
| 东西家持牌 | 完全确定 | 随错误打法不同而变化 |
| 最终回退 | — | `FUN_004188b6` minimax |

## 牌张编码

- `DAT_004b8ab8`：`rank*4 + suit*0x3c`，rank=2-14，suit=0-3 (S/H/D/C)
- DDS bitmask（传给 `dds_calc.exe`）：`1 << rank`（rank 2=0x0004…A=0x4000）
- 模式1序列：`suit*0x14 + rank`
- 模式2序列：`suit*10 + rank`
